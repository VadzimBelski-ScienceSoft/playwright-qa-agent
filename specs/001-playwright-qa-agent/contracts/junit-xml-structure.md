# JUnit XML Structure Contract

**Version**: 1.0.0
**Date**: 2026-02-20

## Overview

This document defines the JUnit XML structure generated by the Playwright QA Agent for CI/CD integration. The structure follows the standard JUnit XML schema with extensions for screenshots and detailed test information.

## XML Schema

```xml
<?xml version="1.0" encoding="UTF-8"?>
<testsuites name="Playwright QA Agent Test Suite"
            tests="{total}"
            failures="{failed}"
            errors="{errors}"
            skipped="{skipped}"
            time="{duration}">

  <testsuite name="Requirements Verification"
             tests="{total}"
             failures="{failed}"
             errors="{errors}"
             skipped="{skipped}"
             time="{duration}"
             timestamp="{ISO8601_timestamp}"
             hostname="{hostname}">

    <properties>
      <property name="session_id" value="{UUID}"/>
      <property name="requirements_file" value="{path}"/>
      <property name="app_url" value="{URL}"/>
      <property name="browser" value="{browser_type}"/>
      <property name="python_version" value="{version}"/>
      <property name="playwright_version" value="{version}"/>
    </properties>

    <!-- Passed test -->
    <testcase classname="requirements"
              name="REQ-001: User can login with valid credentials"
              time="{duration}">
      <properties>
        <property name="requirement_id" value="REQ-001"/>
        <property name="priority" value="P1"/>
        <property name="category" value="authentication"/>
        <property name="screenshot_1" value="screenshots/req_001_before_login.png"/>
        <property name="screenshot_2" value="screenshots/req_001_after_login.png"/>
      </properties>
      <system-out>
[[ATTACHMENT|screenshots/req_001_before_login.png]]
[[ATTACHMENT|screenshots/req_001_after_login.png]]
[14:30:46] Navigating to login page
[14:30:47] Entering credentials
[14:30:48] Clicking login button
[14:30:49] Login successful
      </system-out>
    </testcase>

    <!-- Failed test -->
    <testcase classname="requirements"
              name="REQ-003: User can export reports"
              time="{duration}">
      <properties>
        <property name="requirement_id" value="REQ-003"/>
        <property name="priority" value="P2"/>
        <property name="screenshot_failure" value="screenshots/req_003_failure.png"/>
      </properties>
      <failure message="Element not found: .export-button"
               type="ElementNotFoundError">
[[ATTACHMENT|screenshots/req_003_failure.png]]
Element not found: .export-button

Traceback:
  File "src/services/browser_service.py", line 123, in verify_element
    element = page.locator(selector).wait_for()
  ...
      </failure>
      <system-out>
[14:31:15] Navigating to reports page
[14:31:16] Looking for export button
[14:31:20] ERROR: Export button not found
      </system-out>
    </testcase>

    <!-- Skipped test (needs clarification) -->
    <testcase classname="requirements"
              name="REQ-004: Settings page shows preferences"
              time="{duration}">
      <properties>
        <property name="requirement_id" value="REQ-004"/>
        <property name="clarification_reason" value="Found multiple Settings links"/>
        <property name="screenshot" value="screenshots/req_004_ambiguous.png"/>
      </properties>
      <skipped message="Needs clarification: Found multiple 'Settings' links"/>
      <system-out>
[[ATTACHMENT|screenshots/req_004_ambiguous.png]]
[14:31:25] Navigating to main page
[14:31:26] CLARIFICATION NEEDED: Found multiple Settings links:
  - #settings-menu (top navigation)
  - .user-settings (user dropdown)
  - .admin-settings (admin panel)

Refinement suggestion: Specify which settings page to test (user settings vs admin settings)
      </system-out>
    </testcase>

    <!-- Error (execution error, not test failure) -->
    <testcase classname="requirements"
              name="REQ-005: Dashboard loads within 2 seconds"
              time="0.5">
      <properties>
        <property name="requirement_id" value="REQ-005"/>
      </properties>
      <error message="Network timeout while loading page"
             type="NetworkError">
Network timeout while loading page: https://app.example.com/dashboard

Traceback:
  File "src/services/browser_service.py", line 89, in navigate
    page.goto(url, wait_until='networkidle')
  playwright._impl._errors.TimeoutError: Timeout 30000ms exceeded
      </error>
      <system-out>
[14:31:30] Navigating to dashboard
[14:31:35] ERROR: Network timeout
      </system-out>
    </testcase>

  </testsuite>

</testsuites>
```

## Field Definitions

### `<testsuites>` (Root Element)

| Attribute | Type | Description |
|-----------|------|-------------|
| `name` | string | Suite name (always "Playwright QA Agent Test Suite") |
| `tests` | integer | Total number of test cases |
| `failures` | integer | Number of failed tests |
| `errors` | integer | Number of execution errors |
| `skipped` | integer | Number of skipped tests (needs clarification) |
| `time` | float | Total execution time in seconds |

### `<testsuite>`

| Attribute | Type | Description |
|-----------|------|-------------|
| `name` | string | Suite name (always "Requirements Verification") |
| `tests` | integer | Number of test cases in this suite |
| `failures` | integer | Number of failed tests |
| `errors` | integer | Number of execution errors |
| `skipped` | integer | Number of skipped tests |
| `time` | float | Suite execution time in seconds |
| `timestamp` | string | ISO 8601 timestamp of test run start |
| `hostname` | string | Machine hostname where tests ran |

### `<properties>` (Suite Level)

Global properties for the entire test run:

| Property Name | Description |
|--------------|-------------|
| `session_id` | Unique session UUID |
| `requirements_file` | Path to requirements document |
| `app_url` | Web application URL tested |
| `browser` | Browser type (chromium, firefox, webkit) |
| `python_version` | Python version used |
| `playwright_version` | Playwright version used |

### `<testcase>`

| Attribute | Type | Description |
|-----------|------|-------------|
| `classname` | string | Test class (always "requirements") |
| `name` | string | Test name (format: "REQ-XXX: Title") |
| `time` | float | Test execution time in seconds |

### `<properties>` (Test Case Level)

Properties specific to each requirement test:

| Property Name | Description |
|--------------|-------------|
| `requirement_id` | Requirement ID (REQ-XXX) |
| `priority` | Priority level (P1, P2, P3) |
| `category` | Requirement category |
| `screenshot_{N}` | Path to screenshot N (relative) |
| `clarification_reason` | Why test needs clarification |

### `<failure>`

Used when requirement verification fails:

| Attribute | Type | Description |
|-----------|------|-------------|
| `message` | string | Short error message |
| `type` | string | Error type/class name |

**Content**: Full error message with traceback and screenshot attachments.

### `<error>`

Used when test execution encounters an error (not requirement failure):

| Attribute | Type | Description |
|-----------|------|-------------|
| `message` | string | Short error message |
| `type` | string | Error type/class name |

**Content**: Full error message with traceback.

### `<skipped>`

Used when test is skipped (needs clarification):

| Attribute | Type | Description |
|-----------|------|-------------|
| `message` | string | Reason for skipping |

**Content**: Clarification details and refinement suggestions.

### `<system-out>`

Standard output for the test case.

**Format**:
```
[[ATTACHMENT|path/to/screenshot.png]]  # Screenshot attachments
[HH:MM:SS] Log message                  # Timestamped log messages
[HH:MM:SS] Another message
...
```

**Attachment Markers**:
- Format: `[[ATTACHMENT|{relative_path}]]`
- Must appear at the beginning of system-out
- Supported by Azure DevOps, GitLab CI, and some Jenkins plugins

## Status Mapping

| Playwright QA Status | JUnit XML Element |
|---------------------|------------------|
| `passed` | `<testcase>` (no child elements) |
| `failed` | `<testcase><failure>` |
| `needs_clarification` | `<testcase><skipped>` |
| `error` | `<testcase><error>` |

## CI/CD Integration Examples

### GitHub Actions

```yaml
- name: Publish Test Results
  uses: EnricoMi/publish-unit-test-result-action@v2
  if: always()
  with:
    files: test-results/**/junit.xml
```

### GitLab CI

```yaml
test:
  script:
    - playwright-qa-agent --output test-results requirements.md
  artifacts:
    when: always
    reports:
      junit: test-results/**/junit.xml
```

### Jenkins

```groovy
junit testResults: 'test-results/**/junit.xml'
```

### Azure DevOps

```yaml
- task: PublishTestResults@2
  inputs:
    testResultsFormat: 'JUnit'
    testResultsFiles: '**/junit.xml'
    searchFolder: 'test-results'
```

## Validation Rules

1. **Required Elements**:
   - `<testsuites>` must have exactly one `<testsuite>`
   - Each `<testcase>` must have a unique `name` within the suite
   - Total counts must match: `tests = passed + failed + errors + skipped`

2. **Attribute Constraints**:
   - All time values must be non-negative floats
   - All count values must be non-negative integers
   - `timestamp` must be valid ISO 8601 format

3. **Property Constraints**:
   - `requirement_id` must match pattern `REQ-\d{3}`
   - Screenshot paths must be relative, not absolute
   - All paths must use forward slashes (even on Windows)

4. **Child Element Rules**:
   - `<testcase>` must have zero or one of: `<failure>`, `<error>`, `<skipped>`
   - Cannot have both `<failure>` and `<error>`
   - `<failure>` and `<error>` must have both `message` and `type` attributes

## Example Use Cases

### All Tests Passed

```xml
<testsuites tests="5" failures="0" errors="0" skipped="0" time="12.5">
  <testsuite tests="5" failures="0" errors="0" skipped="0" time="12.5">
    <testcase name="REQ-001: ..." time="2.3"/>
    <testcase name="REQ-002: ..." time="1.8"/>
    <testcase name="REQ-003: ..." time="4.5"/>
    <testcase name="REQ-004: ..." time="2.1"/>
    <testcase name="REQ-005: ..." time="1.8"/>
  </testsuite>
</testsuites>
```

### Mixed Results

```xml
<testsuites tests="5" failures="2" errors="1" skipped="1" time="15.3">
  <testsuite tests="5" failures="2" errors="1" skipped="1" time="15.3">
    <testcase name="REQ-001: ..." time="2.3"/>  <!-- Passed -->
    <testcase name="REQ-002: ..." time="3.2">   <!-- Failed -->
      <failure message="Element not found" type="ElementError"/>
    </testcase>
    <testcase name="REQ-003: ..." time="0.5">   <!-- Error -->
      <error message="Network timeout" type="NetworkError"/>
    </testcase>
    <testcase name="REQ-004: ..." time="1.8">   <!-- Skipped -->
      <skipped message="Needs clarification"/>
    </testcase>
    <testcase name="REQ-005: ..." time="7.5"/>  <!-- Passed -->
  </testsuite>
</testsuites>
```

## Acceptance Criteria

The JUnit XML output must satisfy:

1. **SC-005 (CI/CD Integration)**: Valid JUnit XML that CI/CD systems can parse
2. **SC-008 (Debugging Detail)**: Include screenshots via attachment markers
3. **SC-008 (Debugging Detail)**: Include step-by-step logs in system-out
4. **Validation**: Pass XML schema validation
5. **Portability**: Use relative paths for all file references

## Tools for Validation

```bash
# Validate XML structure
xmllint --schema junit-schema.xsd junit.xml --noout

# View in browser
xunit-viewer --results=junit.xml --output=junit.html
```
